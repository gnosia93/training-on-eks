## DCGM DeepDive ##


### nv-hostengine (호스트 엔진) ###
DCGM 호스트 엔진(nv-hostengine)은 DCGM의 핵심 데몬 프로세스로 DCGM 라이브러리를 감싸고 GPU와 통신하여 관련 메트릭을 수집 및 캐싱한다. 모든 DCGM 클라이언트(dcgmi, DCGM Exporter, Python/Go API 등)는 이 호스트 엔진을 통해 GPU 데이터에 접근하게 된다.
```
┌──────────────────────────────────────────┐
│           클라이언트들                      │
│  dcgmi    DCGM Exporter    Python API    │
│    │           │               │         │
│    └───────────┼───────────────┘         │
│                ▼                         │
│     nv-hostengine (호스트 엔진)             │
│     ├── 메트릭 수집/캐싱                     │
│     ├── 헬스 체크 실행                       │
│     ├── 정책 엔진                           │
│     └── 설정 관리                           │
│                │                         │
│                ▼                         │
│          NVML (드라이버 API)                │
│                │                         │
│                ▼                         │
│           GPU 하드웨어                     │
└──────────────────────────────────────────┘
```
두가지의 실행모드를 가지는데 
* Standalone: nv-hostengine이 독립 데몬으로 실행되고, 여러 클라이언트가 동시에 접속 가능하다. systemd 서비스로 등록하는 게 이 방식이다.
* Embedded: DCGM Exporter 같은 프로세스 안에 라이브러리로 내장되어 실행된다. (별도 데몬 불필요)
  
Kubernetes에서 DCGM Exporter를 쓸 때는 보통 embedded 모드로 동작해서 nv-hostengine을 따로 띄울 필요가 없다. 베어메탈이나 VM에서 직접 쓸 때만 standalone 데몬으로 실행한다. 
NVML 은 Nvidia Management Library 로 NVIDIA 드라이버에 포함된 C 기반 API 라이브러리이다. GPU 하드웨어 정보를 프로그래밍 방식으로 조회하고 관리할 수 있게 해준다. 


### DCGM 설치하기 ###

#### 1단계: NVIDIA 드라이버 확인 ####
AWS 콘솔에서 g6e 인스터스를 프로비저닝 한후 nvidia-smi 로 GPU 정보를 확인한다.  
```
nvidia-smi
```

#### 2단계: DCGM 설치 ####
```
# CUDA keyring 설치 (DCGM 패키지가 이 리포에 포함)
wget https://developer.download.nvidia.com/compute/cuda/repos/ubuntu2404/x86_64/cuda-keyring_1.1-1_all.deb
sudo dpkg -i cuda-keyring_1.1-1_all.deb
sudo apt-get update

sudo apt-get install -y datacenter-gpu-manager

sudo systemctl start nvidia-dcgm
sudo systemctl enable nvidia-dcgm
```

#### 3단계: 설치 확인 ####
```
# GPU 목록 확인
dcgmi discovery -l

# GPU 온도 한 번 조회
dcgmi dmon -e 150 -c 1

# 헬스 체크
dcgmi diag -r 1

# 여러 메트릭 동시 수집 (쉼표로 구분)
dcgmi dmon -e 150,155,252 -c 5
# 150: GPU 온도, 155: 전력, 252: 메모리 사용량. 5번 수집

# 수집 간격 변경 (밀리초)
dcgmi dmon -e 150 -d 1000
# 1초 간격으로 계속 수집 (Ctrl+C로 종료)

# 특정 GPU만 모니터링
dcgmi dmon -e 150 -i 0,1
# GPU 0번과 1번만

# 수집 가능한 전체 Field ID 목록 보기
dcgmi dmon -l
```
* dmon은 device monitor의 약자로 GPU 메트릭을 실시간으로 스트리밍해서 보여주는 서브커맨드.
* -e 150: 수집할 메트릭의 Field ID. 150은 GPU 온도(DCGM_FI_DEV_GPU_TEMP)
* -c 1: count. 1번만 수집하고 종료
* 자주 사용되는 Field ID 로는 150	GPU 온도, 155	전력 사용량, 203	GPU 사용률, 252	메모리 사용량, 1001	GPU Engine Activity, 1004	Tensor Core Activity, 1005	Memory BW Utilization 등이 있다.

#### 참고 - RHEL/Amazon Linux 2023에 설치 ####
```
sudo dnf config-manager --add-repo https://developer.download.nvidia.com/compute/cuda/repos/rhel9/x86_64/cuda-rhel9.repo
sudo dnf install -y datacenter-gpu-manager
sudo systemctl start nvidia-dcgm
sudo systemctl enable nvidia-dcgm
```

### GPU Diagnostics ###
#### Ansible 병렬 실행 ####
[dcgm-diag.yml]
```
- hosts: gpu_nodes
  become: yes
  serial: 20  # 한번에 20노드씩 (전체 묶이는 거 방지)
  tasks:
    - name: Run DCGM Level 3 Diagnostic
      command: dcgmi diag -r 3
      register: diag_result
      timeout: 600  # 10분 타임아웃

    - name: Save result to local
      local_action:
        module: copy
        content: "{{ diag_result.stdout }}"
        dest: "./diag_results/{{ inventory_hostname }}.txt"
```
```
mkdir -p diag_results
ansible-playbook -i inventory dcgm-diag.yml -f 20
```

#### SLURM Job으로 실행 ####
[dcgm-diag.sh]
```
#!/bin/bash
#SBATCH --job-name=dcgm-diag
#SBATCH --nodes=200
#SBATCH --ntasks-per-node=1
#SBATCH --gpus-per-node=8
#SBATCH --output=diag_results/%N.out
#SBATCH --exclusive

srun dcgmi diag -r 3
```
```
mkdir -p diag_results
sbatch dcgm-diag.sh
```
