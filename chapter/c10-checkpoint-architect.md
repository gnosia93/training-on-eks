## S3 ##
```
iter_0001000/
  __0_0.distcp      ← rank 0이 쓴 데이터
  __1_0.distcp      ← rank 1이 쓴 데이터
  ...
  __63_0.distcp     ← rank 63이 쓴 데이터
  .metadata         ← 어떤 텐서의 어느 조각이 어느 파일 어디에 있는지 적은 목록 (rank 0이 씀)
  common.pt, metadata.json   ← Megatron 공통 정보 (rank 0이 씀)
```
* rank마다 각자 파일을 쓴다. rank 0으로 모아서 한 파일로 쓰지 않습니다.
* 병렬 구성이 바뀌어도 다시 나눠 읽을 수 있다는 말은 .metadata 덕분입니다. .metadata에는 텐서마다 전체 크기와 각 조각의 위치가 적혀 있습니다. 그래서 TP=8, PP=2, DP=4로 저장한 체크포인트를 노드 수나 병렬화를 바꾼 뒤에도 읽을 수 있습니다. 각 rank는 새 구성에서 자기가 맡을 부분을 .metadata에서 찾아, 해당 파일의 해당 위치만 읽습니다.



### 학습 재개 ##

프레임워크와 설정에 따라 다른 노드가 쓴 파일이 필요할 수 있습니다. 그래서 어떤 경우든 S3에서 체크포인트 전체를 받아서 재개하는 게 가장 안전합니다. 두 가지만 덧붙이면 됩니다.

프로세스만 죽은 경우도 똑같이 처리합니다. 로컬 파일이 다 남아 있어도 각 노드에는 자기 몫만 있습니다. 다른 노드의 파일이 필요할 수 있다는 점은 노드 장애와 같습니다.
재개 지점은 S3에서 _SUCCESS가 있는 최신 체크포인트입니다. _SUCCESS는 8대의 업로드가 모두 끝나야 생깁니다. 업로드 도중에 장애가 났다면 직전 체크포인트로 돌아가므로, 학습을 최대 1시간 더 잃습니다.

### 로컬 NVMe와 S3의 역할 ###

| 단계 | 로컬 NVMe | S3 |
| :--- | :--- | :--- |
| **저장** | 1-2분 안에 써서 학습이 멈추는 시간을 줄임 | 백그라운드에서 업로드 |
| **복구** | S3에서 받은 파일을 놓는 자리 | 재개 지점을 정하고, 8대 몫 전체를 제공 |

이렇게 보면 NVMe의 역할은 "빨리 쓰기"이고, 복구는 S3가 맡습니다. 원래 STAR가 강조한 것도 저장 시간 단축이라서 이야기가 깔끔해집니다.

대가는 복구 시간입니다. 노드마다 약 1.26 TB를 받아야 해서 몇 분이 걸립니다. 예를 들어 노드당 초당 3-5 GB로 받으면 4-7분입니다. 장애가 월 1회 안팎이면 감당할 만한 시간입니다.


체크포인트는 각 노드의 로컬 NVMe에 1-2분 안에 쓰고, S3로는 백그라운드에서 올렸습니다. 복구할 때는 노드 장애든 프로세스 오류든 S3에서 업로드가 끝난 최신 체크포인트 전체를 받아 재개했습니다. 노드당 1.2 TB라 몇 분이 걸리지만, 프레임워크와 상관없이 항상 같은 방식으로 복구할 수 있어서 단순한 쪽을 택했습니다.



### 분산 체크 포인트의 목적 ###

여러 rank가 동시에 써서 저장을 빠르게 하고, 병렬 구성을 바꿔도 다시 나눠 읽을 수 있게 하는 것입니다. 각 노드가 혼자 복구할 수 있게 만드는 기능은 아닙니다. 기본 설정은 모든 노드가 같은 파일을 볼 수 있는 공유 저장소(공유 파일시스템이나 S3)를 전제로 합니다.

* 예외 1: 노드 로컬 디스크 저장을 전제로 만든 기능은 다릅니다. NVIDIA Resiliency Extension의 local checkpoint가 그런 예입니다. rank마다 자기 상태를 로컬에 두고 다른 노드에 복제본까지 둬서, 로컬에서 바로 복구하도록 설계되어 있습니다.
* 예외 2: FSDP처럼 모든 상태를 나눠 갖는 구성은 대부분 자기 파일만으로 됩니다. 하지만 rank 0만 쓰는 공통 파일과 일부 작은 값 때문에 보장되지는 않습니다.

그래서 복구 설계는 ... 
* 로컬 NVMe: 빨리 쓰는 곳
* S3: 복구할 때 모든 노드가 같이 보는 공유 저장소

분산 체크포인트는 쓰기를 병렬로 하는 기술이고, 읽을 때는 모든 노드가 전체 체크포인트를 볼 수 있어야 한다는 전제가 있습니다. 그래서 저장은 로컬 NVMe에 빠르게 하되, 복구는 S3를 공유 저장소로 써서 전체를 받아 재개하게 했습니다.
